### 0.1 背景

当前 `WorldviewEditor` 将角色、地理、阵营、力量体系、历史、冲突和特殊设定保存在一个世界观大对象中。页面以数组索引定位条目，整页一次保存；来源只有手动、导入和混合三种汇总状态。它可以作为旧数据迁移入口，但不能支撑稳定引用、重名消歧、独立版本、关系、候选确认、分页和并发冲突处理。

统一设定库需要从“填写一份世界观表单”转变为“管理项目事实”。复杂数据能力不能直接暴露成数据库式表格，默认界面以作者熟悉的设定名称、类型、关系句和章节为中心。

### 0.2 目标

1. 覆盖世界观、角色、地点、场景、阵营、物品、冲突、事件、伏笔、规则与限制以及自定义类型；
2. 支持列表、详情和关系视图，1000 条设定条件下仍可搜索、筛选和分页；
3. 明确区分 AI 候选与用户已确认事实、计划章节与正文实际情况；
4. 让来源和历史版本可追溯，恢复不会覆盖或抹去历史；
5. 合并重名设定前展示影响，旧引用不会失效；
6. 桌面和 390px 移动端均能完成查找、创建、编辑、关系维护、确认候选和版本恢复；
7. 稳定 ID、JSON、schema、数据库字段和并发令牌不向普通作者暴露。

### 0.3 非范围

- 不修改前端、后端或迁移代码；
- 不设计社区、分享或多人实时协作；
- 不承诺尚无 API 的交互已可用；
- 不把全项目关系图或复杂图谱布局作为 M1 必须实现的门禁；
- 不设计 M2 伏笔完整生命周期和时间线；
- 不设计 M3 正文版本对比和一致性报告；
- 不复制其他产品的品牌、图标组合或完整页面；
- 不删除或要求删除 `WorldviewEditor` 等核心文件。

## 1. 设计原则

1. **先找得到，再看得懂，再改得安全**：列表负责定位，详情负责理解，编辑和合并负责风险确认。
2. **确认状态独立于来源**：“文档导入”不等于可信，“AI 建议”也不等于错误；是否进入生成依据只由确认状态决定。
3. **关系写成人话**：默认显示“林岚 —效忠于→ 星盟”，不显示 `source_id`、`target_id`、外键或关系表。
4. **稳定身份隐形存在**：重名时通过类型、摘要、关系和来源消歧，不让用户复制内部 ID。
5. **计划与实际并列但不混写**：默认突出偏差，详情才展开两组完整记录。
6. **恢复是新增历史，不是回到过去抹除之后**：恢复旧版本会产生一个新的当前版本。
7. **高风险操作先预览影响**：合并、归档、恢复和自定义类型变更都先说明受影响关系、章节和候选项。
8. **移动端分步完成**：不把桌面三栏压缩到 390px，一次处理一个对象和一组字段。

### 1.1 设计依据与参考边界

本任务没有引入外部产品页面作为视觉模板。方案依据已批准的产品术语、`DES-001` 工作台结构、现有 `WorldviewEditor` 与 API 审查，以及核心开发者正在论证的统一要素/关系/版本边界形成。这样可以避免把其他知识库产品的数据库术语、品牌视觉或完整页面直接搬入小说创作场景。

## 3. 类型体系

### 3.1 全部设定共有信息

每个设定的详情首屏仅要求：

- 名称；
- 类型；
- 一句话摘要；
- 确认状态；
- 来源摘要；
- 最近修改时间；
- 内容字段；
- 关系数量；
- 出现计划与实际记录摘要；
- 当前历史版本。

稳定 ID、字段内部 key、版本令牌和迁移标识仅供系统使用。

### 3.2 内置类型与默认字段

| 类型 | 首屏核心字段 | 详情展开字段 | 推荐关系 |
|---|---|---|---|
| 世界观 | 名称、概述、适用范围 | 核心基调、边界说明 | 包含、遵循、发生于 |
| 角色 | 姓名、身份、性格、目标 | 背景、能力、当前状态、备注 | 亲属、盟友、敌对、隶属、持有、参与 |
| 地点 | 名称、概述、重要性 | 区域、环境、进入条件、备注 | 位于、包含、控制、发生于 |
| 场景 | 名称、目的、故事时间 | 描述、结果、氛围 | 发生于地点、参与角色、涉及事件/冲突 |
| 阵营 | 名称、立场、目标 | 实力、状态、备注 | 隶属、联盟、敌对、控制 |
| 物品 | 名称、能力、限制 | 来源、当前状态、备注 | 持有、争夺、来自、影响 |
| 冲突 | 名称、参与方、诉求 | 赌注、状态、解决线索 | 驱动、影响、涉及、对抗 |
| 事件 | 名称、故事时间、结果 | 描述、影响 | 发生于、参与、导致、阻止、呼应 |
| 伏笔 | 描述、目标、当前状态 | 说明、关联对象 | 指向、呼应、涉及 |
| 规则与限制 | 名称、规则、适用条件 | 例外、违反后果、说明 | 约束、适用于、影响 |
| 自定义类型 | 名称、摘要、用户字段 | 来源、关系、章节记录、版本 | 通用关系和用户允许的关系 |

“地点”与“场景”是不同内置类型。“地点”表示小说世界中的空间；“场景”表示一段有时间、地点、参与者和目的的叙事场面。场景通过关系选择已有地点，不把地点名称重复保存为难以追踪的纯文本。旧 `geography` 迁移为地点，不自动猜测为场景。

### 3.3 伏笔入口

伏笔可以在设定库中被搜索、查看来源和参与关系，但创建、埋入、强化、回收和逾期处理的主要入口仍是“计划 > 伏笔”。设定库详情只展示生命周期摘要和前往计划的链接，避免出现两套可写状态。

### 3.4 自定义类型

创建自定义类型采用两步向导：

1. **定义用途**：类型名称、单数显示名、说明、图标颜色；
2. **添加字段**：从短文本、长文本、数字、日期、开关、单选、多选、关联设定中选择。

每个字段只让用户配置：

- 显示名称；
- 帮助说明；
- 是否必填；
- 选项（适用时）；
- 是否在列表摘要中显示。

不显示 JSON、schema、主键、数据类型编码或内部字段 key。

已有实例后：

- 可以重命名显示名称、修改帮助说明和排序；
- 可以新增字段；
- 可以把旧字段标为“停止使用”，历史值仍可查看；
- M1 不允许直接把已有字段从文本改为数字等破坏性类型；
- 删除自定义类型必须另行评估数据影响，本设计默认只提供归档。

## 4. 信息架构与路由

### 4.1 页面层级

```text
设定库
├── 全部设定
├── 待确认
│   ├── 导入批次
│   └── 候选设定详情
├── 类型筛选
│   ├── 世界观 / 角色 / 场景 / 阵营 / 物品
│   ├── 冲突 / 事件 / 伏笔 / 规则与限制
│   └── 自定义类型
├── 设定详情
│   ├── 内容
│   ├── 关系
│   ├── 出现记录
│   ├── 来源
│   └── 历史版本
├── 关系视图
└── 已归档
```

### 4.2 推荐路由

为避免与“项目设置”混淆，建议把 `DES-001` 的过渡 `/settings` 最终确定为：

| 页面 | 路由 |
|---|---|
| 设定库 | `/project/:id/lore` |
| 设定详情内容 | `/project/:id/lore/:elementId` |
| 详情关系 | `/project/:id/lore/:elementId/relations` |
| 出现记录 | `/project/:id/lore/:elementId/appearances` |
| 来源 | `/project/:id/lore/:elementId/source` |
| 历史版本 | `/project/:id/lore/:elementId/history` |
| 关系视图 | `/project/:id/lore/relations` |
| 待确认 | `/project/:id/lore/review` |
| 指定导入批次 | `/project/:id/lore/review/:batchId` |
| 自定义类型管理 | `/project/:id/lore/types` |

路由内部使用稳定 ID，但界面只显示名称。若访问已合并对象的旧链接，导航到保留项并显示“此设定已合并到『…』”；不得显示 404 或暴露内部重定向机制。

### 4.3 默认入口

- 第一次进入且没有设定：空白引导页；
- 有待确认候选且没有已确认设定：默认显示“待确认”并说明确认后的影响；
- 已有设定：显示全部已确认且未归档的设定；
- 从章节或关系跳入：打开指定详情并保留来源页返回路径；
- 刷新和浏览器返回：恢复路由、筛选、排序、页游标及列表滚动位置。

## 5. 桌面布局

### 5.1 `≥1440px`

在 `DES-001` 的 240px 项目导航之外，设定库内容区使用三栏：

| 区域 | 宽度 | 内容 |
|---|---:|---|
| 筛选与设定列表 | `280px` | 搜索、状态/类型筛选、分页列表 |
| 设定详情 | `minmax(600px, 1fr)` | 内容表单或关系编辑 |
| 上下文栏 | `320px` | 来源、关系摘要、出现偏差、版本摘要 |

顶部沿用 64px `ContextHeader`，面包屑为 `项目名 / 设定库 / 当前设定`。三栏独立滚动，但保存状态和页面主操作保持可见。

### 5.2 `1024–1439px`

- 列表 `280px` + 详情区；
- 上下文栏改为右侧抽屉；
- 详情顶部提供“关系 / 出现 / 来源 / 版本”分段导航；
- 抽屉宽 `min(420px, 45vw)`。

### 5.3 `769–1023px`

- 列表 `240px` + 详情区；
- 筛选器除类型外收进筛选抽屉；
- 关系、来源、版本均进入独立子路由；
- 编辑表单最多两列，字段较长时单列。

### 5.4 列表空选状态

桌面没有选中设定时，详情区显示：

- 当前筛选结果数量；
- 最近打开的设定；
- “新建设定”主操作；
- 键盘提示（若用户已启用快捷键）；
- 不自动选中第一项，避免用户误以为已进入某条设定。

## 6. 390px 移动布局

### 6.1 页面层级

移动端采用“列表页 → 独立详情页 → 独立子页”，不保留桌面分栏：

1. 设定库列表；
2. 设定详情；
3. 编辑内容；
4. 关系；
5. 出现记录；
6. 来源；
7. 历史版本；
8. 候选确认；
9. 自定义类型。

移动顶栏高 `56px`，底部工作台导航沿用 `DES-001` 的 `64px + safe-area`。详情页底部不再加第二套固定标签栏，采用内容中的 `44px` 行入口，防止垂直空间被多层导航占用。

### 6.2 列表页

- 顶部搜索框高 `44px`；
- 第二行显示横向可滚动的类型筛选 chip，但首尾必须有渐隐提示；
- “筛选”按钮显示已启用条件数量；
- 每条设定卡最小高 `76px`，包含名称、类型、状态、两行摘要；
- 待确认与已确认不混在无标识的同一结果中；
- 每页建议 20 条，触底显示明确“加载更多”，不做无限自动加载；
- 返回列表恢复原筛选和滚动位置。

### 6.3 详情页

首屏顺序：

1. 名称、类型和确认状态；
2. 一句话摘要；
3. 主操作（编辑或确认）；
4. 内容摘要；
5. 关系；
6. 出现记录；
7. 来源；
8. 历史版本。

各次级区域用 `44px` 可点击行进入独立页面，并显示数量或状态摘要。稳定 ID、版本令牌和完整迁移信息不出现。

### 6.4 移动编辑

- 基础字段单列；
- 首屏只显示名称、摘要和 2–4 个核心字段；
- “更多内容”展开其余字段；
- 底部固定操作区高 `64px + safe-area`，包含“取消”和“保存”；
- 软键盘打开时固定操作区可以改为表单底部静态区域，不能遮住当前字段；
- 保存失败保留所有输入；
- 切换页面前检测未保存修改。

## 7. 列表、搜索、筛选与分页

### 7.1 列表项信息

列表项固定展示：

- 类型图标与类型名；
- 设定名称；
- 最多两行摘要；
- `待确认 / 已确认 / 已归档 / 已合并` 状态之一；
- 最近修改时间；
- 有偏差时显示“出现计划有 1 项偏差”，不显示无依据的风险数字。

来源、关系数和章节数只在空间允许时显示，不能让列表变成数据表。

### 7.2 搜索

搜索范围：

- 名称；
- 别名；
- 摘要；
-结构化文本字段；
- 关系目标名称（服务端能力允许时）。

交互规则：

- 输入后 `300ms` 防抖；
- 搜索请求有序号，旧响应不能覆盖新结果；
- 查询为空时恢复当前筛选的默认列表；
- 没有结果时保留查询与筛选，并提供清除筛选；
- 重名结果同时显示类型、摘要和一条关键关系；
- 不允许通过内部 ID 搜索作为普通功能。

### 7.3 筛选

M1 必备筛选：

- 类型；
- 确认状态；
- 来源；
- 是否有关联章节；
- 是否存在关系；
- 已归档；
- 最近修改时间。

“计划与实际不一致”依赖 M2 数据完整后启用；M1 可保留明确规划状态，不显示假结果。

### 7.4 排序

- 默认：最近修改；
- 可选：名称、创建时间、类型；
- 有搜索词时默认相关度；
- 排序必须稳定，使用系统内部身份作为最后稳定条件但不显示。

### 7.5 分页

- 采用服务端 cursor 分页，不一次加载 1000 条；
- 桌面默认每页 30 条；移动每页 20 条；
- 桌面使用“上一页 / 下一页”并维护游标栈，不承诺任意页码跳转；移动使用“加载更多”；
- cursor 由排序值和稳定 ID 组成不透明令牌，界面不显示其内容；
- 响应提供 `next_cursor`、`has_more` 和当前筛选的精确 `total`；分类数量通过同一响应或独立 facets 查询获得；
- 分类统计包含类型、确认状态和来源，不能通过前端全量扫描计算；
- 翻页后保持筛选、排序和搜索；
- 归档、合并或恢复导致当前页数量变化时，保留上下文并说明结果位置变化；
- 名称、时间和类型排序都以稳定 ID 作为最终排序条件，防止翻页重复或遗漏。

## 8. 创建与编辑

### 8.1 新建设定

流程：

1. 点击“新建设定”；
2. 选择内置或自定义类型；
3. 填写名称、摘要和类型核心字段；
4. 可选添加关系；
5. 保存；
6. 新建的手动内容默认进入“已确认”，详情显示“手动创建”来源。

类型选择器按“常用 / 其他 / 自定义”分组，并支持键盘搜索。类型卡说明用途，不显示字段数量或数据表名。

### 8.2 编辑

- 详情默认只读，点击“编辑”进入表单；
- 保存前前端做必填和格式检查，服务端仍为最终判断；
- 成功后生成新历史版本；
- 名称修改不改变任何关系或章节引用；
- 切换类型不是普通编辑项；错误类型通过“转换类型”专项流程处理并预览字段影响；
- 编辑关系和出现计划不应与内容表单混在同一个巨大提交中。

### 8.3 表单结构

| 区块 | 默认状态 | 内容 |
|---|---|---|
| 基本信息 | 展开 | 名称、摘要、类型 |
| 类型内容 | 展开 | 类型核心字段 |
| 更多内容 | 收起 | 非高频字段、备注 |
| 关系 | 摘要 | 跳转到关系编辑 |
| 出现记录 | 摘要 | 计划/实际偏差及跳转 |
| 来源 | 摘要 | 创建方式和原文位置 |
| 历史版本 | 摘要 | 当前版本和最近变更 |

## 9. AI 导入候选与用户确认

### 9.1 候选收件箱

AI 解析结果进入独立“待确认”队列，不直接混入已确认事实。批次页展示：

- 文件名或导入来源；
- 解析时间；
- 候选总数；
- 已确认、待处理、已忽略和失败数量；
- 按类型分组的候选列表；
- 部分失败说明和重试范围。

### 9.2 候选卡

每项展示：

- AI 建议标签；
- 建议类型和名称；
- 摘要；
- 原文片段及位置；
- 可能重复的已有设定；
- 关系建议数量；
- `确认 / 编辑后确认 / 合并到已有 / 忽略`。

不显示没有可解释依据的精确“可信度百分比”。若系统只有模型置信分，不将其伪装为事实概率。

### 9.3 确认规则

- “确认”是明确用户动作；
- 批量确认仅适用于没有重复候选、必填缺失和关系冲突的项目；
- 确认设定不自动确认它的关系建议，除非界面明确列出并由用户勾选；
- 忽略不会删除原始导入批次；可以在批次中重新查看；
- 未确认候选不得出现在章节生成依据选择器中；
- 导入解析失败不得覆盖已有设定。

## 10. 详情与来源

### 10.1 详情页

详情顶部展示：

- 名称；
- 类型；
- `待确认 / 已确认 / 已归档 / 已合并`；
- 一句话摘要；
- 最近修改；
- 主操作；
- 更多菜单。

更多菜单包含历史版本、合并、归档；高风险操作不放在主按钮位置。

### 10.2 来源

来源按时间顺序列出，可以有多条：

- 手动创建；
- 文档导入；
- AI 建议；
- 正文提取；
- 合并来源；
- 版本恢复。

每条来源展示可用的信息：时间、操作、文件或章节、原文片段、执行者。没有来源位置时显示“未保留原文位置”，不能伪造。

来源状态和确认状态使用不同组件：

- `来源：文档导入`
- `状态：已确认`

不得显示“已导入”来暗示内容已经过用户确认。

## 11. 关系编辑

### 11.1 默认关系视图

M1 默认采用可分页的自然语言关系列表：

```text
林岚（角色） — 效忠于 → 星盟（阵营）
星盟（阵营） — 敌对于 → 黑潮议会（阵营）
旧王冠（物品） — 持有者是 → 林岚（角色）
```

列表按“从此设定出发 / 指向此设定”分组，用户不必理解出边和入边。

### 11.2 新增关系

流程：

1. 当前设定固定为关系起点；
2. 选择关系词；
3. 搜索并选择目标设定；
4. 可选填写说明；
5. 查看完整关系句和反向阅读句；
6. 保存。

目标搜索结果必须展示：

- 名称；
- 类型；
- 摘要；
- 一条关键关系或来源；
- 重名标识。

不显示内部 ID。

### 11.3 方向

关系选择器显示：

- 正向：`林岚 效忠于 星盟`
- 反向：`星盟 的成员包括 林岚`

用户可以交换起点和目标，但不能仅用箭头方向表达含义。关系类型如果没有合理反向词，显示“与…存在…关系”，不能自动编造。

### 11.4 校验与冲突

- 重复关系：提示已有关系并提供打开；
- 自环关系：默认阻止，只有明确允许的关系类型才能保存；
- 类型不匹配：解释期望类型并允许重新选择；
- 目标已归档：默认不出现在搜索中，已有关系显示归档状态；
- 目标已合并：自动指向保留项并向用户说明；
- 目标在保存前被修改或合并：返回冲突，不静默绑定旧目标；
- 删除关系：先说明只移除联系、不影响两个设定；成功后提供短时撤销。

### 11.5 关系焦点视图

桌面可提供单个设定的一跳关系图作为增强：

- 当前设定居中；
- 默认最多 30 个邻接设定；
- 按类型或关系筛选；
- 点击邻接点打开详情或设为新的中心；
- 不自动加载整个项目；
- 始终提供等价关系列表；
- 390px 不要求图视图，只提供关系列表。

关系图不是 M1 核心验收门禁；如果性能、依赖或可访问性成本显著，应延后到 M4，不能阻塞稳定关系列表。

## 12. 出现计划与实际记录

详情页只展示同一设定的章节关联：

| 区域 | 内容 | 编辑权限 |
|---|---|---|
| 计划 | 首次出现、引用、揭示的计划章节 | 依赖 M2 章节计划 API；未启用时显示规划状态 |
| 正文记录 | 已确认正文中实际出现、引用和揭示的章节 | 只读；由用户确认正文后的提取结果产生 |
| 偏差 | 提前出现、计划未执行或多次首次出现 | 跳转检查；M3 前不显示模拟问题 |

规则：

- 默认先显示偏差摘要；没有偏差时显示“计划与正文记录一致”；
- 展开后再显示两组完整列表；
- 修改计划不能静默改写正文记录；
- 正文记录不能在设定库内直接编辑，需定位到章节；
- 同一设定只能有一个计划首次出现章节；
- M1 若 API 未就绪，入口保留并标明依赖，不提供假编辑控件。

## 13. 历史版本与恢复

### 13.1 历史列表

每条版本展示：

- `版本 12` 等用户可读序号；
- 修改时间；
- 修改来源；
- 修改摘要；
- 是否当前版本；
- 操作者（存在时）。

普通界面不显示哈希、数据库 revision 或 ETag。

### 13.2 查看版本

M1 最低能力：

- 查看任一版本的完整只读内容；
- 显示相对上一版的变更字段名称；
- 按字段展示旧值和新值，不承诺字符级或语义差异；
- 可并排查看当前版与选中版（桌面）；
- 移动端按字段上下排列；
- 内容版本只包含类型、名称、摘要、结构化内容和当时的类型定义版本；
- 关系和章节绑定拥有各自独立历史，不进入内容版本；来源历史也不会被内容恢复覆盖。

字段级字符 diff 是增强项，不是 M1 必须门禁；系统不能准确生成时只显示两版完整字段，不给出误导性差异。

### 13.3 恢复

流程：

1. 选择历史版本；
2. 查看内容和与当前版的差异摘要；
3. 明确查看“不会改变”的关系、出现记录、来源和确认/归档状态；
4. 确认“仅以此内容创建一个新版本”；
5. 保存成功后跳到新版本详情；
6. toast 显示“已根据版本 8 创建版本 13”。

恢复不修改旧版本，不把当前版本号倒退，也不静默覆盖并发修改。

## 14. 合并与归档

### 14.1 合并重复设定

合并采用“预览 → 选择保留项 → 解决字段冲突 → 确认”：

1. 搜索并选择另一条设定；
2. 指定哪条作为保留项；
3. 并排比较名称、内容、来源和确认状态；
4. 对冲突字段逐项选择或手动编辑；
5. 预览受影响关系、章节、候选和版本；
6. 确认后，旧引用指向保留项；
7. 访问旧对象时显示“已合并到…”。

合并后：

- 保留双方来源；
- 保留被合并对象的历史；
- 保留项产生新版本；
- 被合并项不出现在普通列表；
- 不提供“直接删除重复项”替代合并。

### 14.2 归档

归档确认框说明：

- 将从常用列表和新关系选择器中隐藏；
- 已有关系和章节记录不会消失；
- 可以从“已归档”恢复；
- 若仍被计划或正文引用，先列出引用数量和入口。

永久删除、保留期限和隐私擦除不属于 `DES-002`，必须由数据治理任务单独决策。

## 15. 状态规范

### 15.1 状态矩阵

| 状态 | 呈现 | 主操作 | 保留内容 |
|---|---|---|---|
| 列表初次加载 | 设定卡骨架，保留项目导航与搜索位 | 无 | 当前路由 |
| 列表分页加载 | 列表底部 3 条骨架 | 取消不要求 | 已有结果和滚动位置 |
| 全库空白 | 解释设定库用途 | 新建设定；次操作导入 | 无 |
| 筛选无结果 | 显示当前搜索和筛选 | 清除筛选 | 搜索词 |
| 详情加载 | 标题与字段骨架 | 无 | 列表选中态 |
| 详情 404 | “设定不存在或已被合并” | 返回列表；有重定向则查看保留项 | 列表上下文 |
| 权限错误 | 不泄露对象内容 | 返回项目 | 已输入的本地草稿需可复制 |
| 列表/详情错误 | 内联说明错误范围 | 重试 | 旧数据、筛选、草稿 |
| 表单校验错误 | 字段内说明 + 顶部摘要 | 修正 | 全部输入 |
| 保存中 | 固定保存状态，按钮禁用 | 无 | 全部输入 |
| 保存成功 | 就地更新 + toast | 查看新版本 | 路由与筛选 |
| 保存失败 | 常驻“未保存” | 重试；复制草稿 | 全部输入 |
| 409 冲突 | 阻止覆盖，显示服务器更新时间 | 查看差异；重新加载；保留本地副本 | 本地草稿 |
| 候选解析中 | 批次级进度和已解析数量 | 可离开页面 | 已有设定不受影响 |
| 候选部分失败 | 成功项和失败项分组 | 重试失败项 | 已成功候选 |
| 候选待确认 | AI 建议标签和来源 | 确认/编辑/合并/忽略 | 原文来源 |
| 关系目标失效 | 关系行内警告 | 选择新目标/查看合并项 | 关系说明 |
| 版本加载/恢复中 | 版本区局部状态 | 无 | 当前详情 |
| 恢复成功 | 显示新版本号 | 查看新版本 | 完整历史 |
| 合并预览过期 | 说明数据已变化 | 重新生成预览 | 用户选择草稿 |
| 迁移中 | 全库只读横幅，显示进度或阶段 | 稍后重试 | 所有现有数据 |
| 迁移失败 | 阻断写入但允许读取安全数据 | 重试/联系支持 | 原数据 |
| 功能依赖未就绪 | `StageNotice` 说明里程碑和替代路径 | 前往可用功能 | 不显示假数据 |

### 15.2 409 版本冲突

出现“内容已被更新”时：

1. 立即停止此对象的自动保存；
2. 保留本地草稿；
3. 获取服务器当前版本摘要；
4. 提供查看差异、重新加载、复制本地内容；
5. 若支持合并，用户逐字段处理；
6. 不提供默认“强制覆盖”；
7. 关系、合并和版本恢复也必须携带预期版本或等价并发保护。

### 15.3 禁用状态

禁用控件旁必须写原因，例如：

- “请先确认这条 AI 建议，再把它用于章节计划。”
- “项目正在迁移，暂时只能查看。”
- “该设定已合并，请前往保留项编辑。”

不能只降低透明度或只用锁图标。

## 18. 键盘与可访问性

1. 使用 `main`、`nav`、`aside`、`section` 和正确标题层级；
2. 列表项使用可聚焦链接，当前详情使用 `aria-current`，不把整行做成无语义 `div`；
3. 搜索可使用 `/` 快捷键，但焦点在输入框时不得触发；界面需允许关闭快捷键；
4. 目标选择器遵循 combobox/listbox 语义，支持上下键、Enter、Esc 和输入过滤；
5. 关系方向不能只用箭头，必须有可读关系句；
6. 关系图必须提供等价列表，键盘和读屏器不依赖拖动画布；
7. 分页或加载更多完成后，焦点保留在触发按钮或移动到新增结果标题，不跳回页首；
8. 表单错误通过 `aria-describedby` 关联，提交后聚焦错误摘要；
9. 状态变化使用 `aria-live="polite"`；409 和迁移失败使用阻断警报；
10. 对话框和抽屉圈闭焦点，`Esc` 关闭并恢复到触发器；
11. 历史版本对比以字段标题组织，新增/删除/修改不只靠颜色；
12. 所有拖拽排序提供“上移/下移”按钮；
13. 支持 `prefers-reduced-motion`，关系图移动和抽屉动画可关闭；
14. 普通文字对比度至少 `4.5:1`，焦点和图形控件至少 `3:1`；
15. 200% 缩放下不能丢失列表、保存、关系和返回入口。

## 19. 现有实现迁移策略

### 19.1 可复用

- React Router、`ProtectedRoute` 和项目加载逻辑；
- `WorldviewEditor` 的文档上传、解析触发和旧类型字段文案可作为迁移参考；
- 现有 `WorldviewSource` 可映射到新来源记录的初始类型；
- 现有 `WorldviewElement` 的名称、类别、描述和优先级可作为迁移候选；
- 现有卡片、按钮、输入框视觉 token。

### 19.2 不继续扩展

- 不继续在 `WorldviewData` 大对象上追加场景、物品、版本和关系数组；
- 不继续使用数组索引作为设定身份；
- 不继续用整页保存覆盖所有设定；
- 不继续用 `alert()` 作为导入、保存和错误的主要反馈；
- 不继续以模式切换决定整页只读；
- 不继续把“进入下一步”作为设定完成后的唯一路径。

### 19.3 并行迁移

- 原 `WorldviewEditor` 保留为旧数据兼容/迁移入口；
- 新设定库使用独立路由和 API；
- 迁移完成并验收前，不要求删除、清空或大幅重写旧组件；
- 旧链接进入兼容页或跳转说明；
- 任何淘汰核心文件的需求必须另行走 `AGENTS.md` 审批。

- 390px 独立子路由的成本与草稿风险；
- `WorldviewEditor` 可复用与仅兼容部分。

### 20.2 最高管理者临时技术草案与网站设计复核

核心开发 Agent 此前提供过 cursor 分页、邻接关系、独立版本边界、合并事务和移动草稿等初步技术输入，该历史事实保留。`coordination/domain-model.md` v1.0 则是项目负责人授权最高管理者临时编写的技术草案，并非核心开发者正式交付。

网站设计者对该临时技术草案完成复核，判断以下边界能够支撑 `DES-002` 并建议进入 `REVIEW`：

- 列表 API 使用 cursor；桌面维护游标栈，移动加载更多；
- 列表响应提供精确 `total` 及类型、状态、来源 facets，1000 条规模配合复合索引可接受；
- 列表只返回摘要、状态、当前版本、revision 及关系/绑定计数；完整 payload、来源和轻量计数在详情加载；
- 写入使用 `If-Match` 或 `expected_revision`，409 返回服务器修订摘要，内部令牌不展示；
- 关系采用当前要素的入/出邻接 cursor 分页，正反向文案来自关系类型定义；一跳图延后；
- 内容版本不包含关系和章节绑定；三者独立记录历史；
- M1 提供整版查看和字段级旧值/新值，不做字符级或语义差异；
- 合并必须 preview/commit 两步，并在单事务内重定向引用、去重关系和产生新版本；
- 移动内容草稿按用户、项目、设定和基础 revision 隔离，关系、合并、恢复使用独立短事务；
- `WorldviewEditor` 只复用字段文案、上传解析和旧对象读取，不继续扩展数组身份与整体覆盖保存。

开发者另外指出旧 `geography` 不能迁移为叙事场景。最终技术草案已增加内置“地点”类型并建立独立地点/场景语义。

### 20.3 采纳、调整与未采纳

已采纳：

- 统一要素和独立关系/版本/章节绑定边界；
- 版本不可变、恢复产生新版本；
- 计划与实际隔离；
- 自定义类型通过类型定义驱动，不直接追加固定前端表单；
- 稳定 ID 仅在系统内部使用。
- 多来源记录及来源位置；
- AI 候选与用户确认分离；
- 合并采用影响预览与旧引用重定向；
- 关系默认采用邻接列表，关系图为增强；
- 服务端分页、稳定排序和 409 并发保护；
- 迁移期间只读与失败状态。
- 新增地点类型，旧 `geography` 映射为地点；
- 内容、关系和章节绑定分别展示历史；
- 内容恢复不会修改来源或生命周期状态；
- 移动本地草稿默认 7 天过期并在退出登录时清理。

调整：

- 桌面不提供任意页码跳转，使用 cursor 的上一页/下一页；
- “恢复版本”改为“仅恢复设定内容”，明确关系、出现记录、来源和生命周期状态不变；
- 一跳关系图从可选 M1 增强进一步明确为不阻塞 M1。

未采纳：

- 无。核心开发者意见均与产品目标及 `DES-002` 体验门禁一致。

## 21. 风险与需决定项

### 21.1 当前风险

- 自定义类型无法完全无损投影回旧七类 JSON，生产回滚前必须导出并向用户说明；
- 一次加载全量关系会在 1000 条设定条件下产生性能和可访问性问题；
- M1 与 M2 的章节出现能力边界需在 API 中明确，避免展示可编辑假控件；
- 关系图可能引入额外依赖，不应阻塞核心关系列表；
- 现有 CSS 焦点可见性不足，实施时必须补可见焦点。

### 21.2 需要最高管理者决定

1. 是否批准最终使用 `/project/:id/lore`，避免与项目设置的 `/settings` 混淆；
2. 是否批准增加内置“地点”类型，将旧 `geography` 无损迁移为地点而非叙事场景；
3. 是否批准 M1 关系图为增强项、自然语义关系列表为验收门禁；
4. 是否批准已有实例的自定义字段禁止直接改类型，只能新增和停用；
5. 是否批准 M1 默认只提供归档与合并，不提供永久删除；
6. 是否批准章节出现计划在 M1 仅展示依赖/摘要，完整编辑进入 M2。
