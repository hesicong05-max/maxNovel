## 管理结论

当前代码是一套可继续演进的“世界观导入—大纲生成—章节续写”原型，不需要推倒重来。认证、项目隔离、AI 流式生成、世界观解析、大纲和章节编辑等基础能力已经存在。

但若按新的 AI 小说创作平台目标验收，当前只能评为“核心基础部分具备、领域能力尚未成型”。最关键的差距不是页面数量，而是设定仍主要存放在单条世界观记录的 JSON 字段中，缺少可独立引用、版本化、绑定章节和追踪生命周期的统一领域模型。

建议冻结社区功能扩张，把未来 8–10 周集中在：

1. 统一设定模型与关系；
2. 章节精确绑定与首次出现；
3. 伏笔埋入、强化和回收；
4. 生成依据、版本与冲突报告；
5. 长篇上下文和时间线一致性；
6. 移动端、可访问性、数据删除和发布门禁。

## 主要问题与优先级

### P0：阻塞产品核心目标

1. **领域模型无法支撑精确引用。** 世界观、角色、势力、事件等集中在 JSON 数组；场景、物品、自定义要素缺失；关系没有数据库级身份和约束。
2. **一致性检查没有接入主流程。** `ConsistencyChecker` 仅被单元测试调用；角色状态、伏笔埋入和回收方法也没有生产调用方。
3. **用户无法管理章节绑定。** 当前揭示计划由 AI 生成，界面只读展示，不能明确配置首次出现、插入、强化和回收章节。
4. **缺少版本与溯源。** 保存世界观会删除旧记录后重建；章节和大纲重新生成会覆盖内容；无法比较或恢复历史版本。
5. **删除项目会遗留独立文件。** 数据库项目被删除后，`data/projects/{project_id}` 没有同步清理，存在用户数据残留风险。
6. **移动端主导航不可用。** 768px 以下侧栏直接隐藏，没有菜单或底部导航替代。

### P1：影响质量和交付可信度

1. 项目最多 50 章，与长篇小说目标不符；上下文只保留最近 5 章摘要和最近 10 条时间线事件。
2. 章节人工编辑后只生成截断式摘要，没有重新提取角色状态、事件、伏笔，也不会触发后续计划影响分析。
3. 关系字段虽然存在于类型和后端 Schema 中，但世界观编辑器没有关系编辑界面。
4. `outline.py`、`chapters.py`、`ChapterWriter.tsx` 等文件体积过大，后续扩展容易产生回归。
5. CI 只显式运行部分后端测试文件；约 177 个测试函数所在文件未进入 CI。安全扫描使用 `|| true`，发现问题也不会阻止合并。
6. 当前机器没有安装后端依赖，无法复现旧报告中的全量后端通过结论；仓库也没有一条完整的本地一键验证命令。
7. 根目录 `.env.prod` 被 Git 跟踪，但部署指南要求根目录 `.env`，README 又主要描述 `backend/.env.prod`，配置来源容易混淆。
8. 项目列表按项目逐个查询世界观、大纲和章节数，存在明显 N+1 查询。

### P2：体验和维护问题

1. 登录页多数输入和按钮高度为 33–40px，移动端触控目标偏小。
2. 除表单输入外缺少一致的键盘焦点样式，也没有减少动画偏好处理。
3. 章节工作区使用固定 `200px + 1fr` 网格，移动端没有专门布局规则。
4. 大量内联样式和原生 `alert/confirm`，难以形成统一状态组件与视觉验收。
5. README、旧设计文档和多份上线报告存在定位与能力描述差异，需要建立单一事实来源。
