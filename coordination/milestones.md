# 项目里程碑

## 规划假设

- 规划基线：2026-07-30
- 团队容量：1 名核心开发者、1 名网站设计者、1 名最高管理者
- 周期估算：8–10 周，不包含外部采购、生产域名和第三方合规审批
- 产品范围：优先完成 AI 小说创作核心闭环；社区功能在 Beta 前仅修复严重缺陷

## M0：范围锁定与交付基线

- 建议周期：第 1 周
- 里程碑目标：统一产品术语、验收边界、数据安全和持续集成基线
- 出口标准：
  - MVP 能力地图、术语表和非目标清单获得最高管理者批准；
  - 全部后端测试进入 CI，安全扫描可阻止高严重度问题；
  - 项目删除能够处理所有持久化副本；
  - 本地和 CI 均有一条可复现的验证命令；
  - 核心工作台信息架构与状态清单通过设计评审。

### `PM-002` 产品范围与术语基线

- 状态：`APPROVED`
- 负责人：最高管理者
- 优先级：P0
- 背景与目标：消除“世界观续写工具”和“AI 小说创作平台”之间的口径差异。
- 范围：MVP 能力地图、要素分类、章节绑定术语、伏笔状态、版本语义、非目标。
- 不包含：底层表结构和具体组件实现。
- 依赖：`PM-001`
- 验收标准：
  - 每项核心能力均有用户故事和可验证结果；
  - 明确“首次出现、引用、揭示、伏笔埋入、强化、回收”的区别；
  - 明确 Beta 前不扩张的功能；
  - 开发者和设计者均确认无重大歧义。
- 交付物：`coordination/product-scope.md`

### `DEV-001` 测试、删除与环境基线

- 状态：`APPROVED`
- 负责人：核心开发者
- 优先级：P0
- 背景与目标：让已有原型具备可信的继续开发基线。
- 范围：CI 全量测试、数据副本删除、环境文件口径、验证脚本、迁移测试。
- 不包含：新领域模型和新页面。
- 依赖：`PM-001`
- 验收标准：
  - CI 运行 `backend/tests` 全目录和前端测试、类型检查、构建；
  - 高严重度安全扫描失败时 CI 失败；
  - 删除项目后数据库和项目文件均无残留；
  - 新开发者按 README 可完成一次验证；
  - 原有测试全部通过。
- 交付物：代码、测试、README 更新、开发报告。

### `DES-001` 核心创作工作台信息架构

- 状态：`APPROVED`
- 负责人：网站设计者
- 优先级：P0
- 背景与目标：把固定三步流程升级为用户可理解的长篇创作工作台。
- 范围：桌面和移动信息架构、设定库、章节计划、伏笔、时间线、检查报告入口，以及加载、空白、错误、禁用、成功状态。
- 不包含：完整品牌重设计和社区页面。
- 依赖：`PM-002` 的术语可先用草案推进，最终以批准版校正。
- 验收标准：
  - 桌面与 390px 移动端均可到达所有核心功能；
  - 用户始终知道正在编辑的项目、章节和设定；
  - 高频操作不暴露数据库或 Prompt 等技术概念；
  - 与开发者完成一次可行性评审。
- 交付物：设计报告、页面流、组件和状态规范。

## M1：统一设定模型与设定库

- 建议周期：第 2–3 周
- 里程碑目标：所有小说设定拥有稳定身份、关系、版本和来源，可独立编辑和引用。
- 出口标准：
  - 支持世界观、角色、场景、阵营、物品、冲突、事件、伏笔、规则与自定义要素；
  - 要素关系引用稳定 ID，不依赖名称匹配；
  - 每次修改产生版本记录，可查看来源并恢复；
  - 现有世界观 JSON 可无损迁移，迁移可回滚；
  - 设定库桌面与移动核心流程通过验收。

### 任务

- `DEV-002`：领域模型、迁移和兼容方案，`APPROVED`，依赖 `PM-002`；由项目负责人授权最高管理者临时编写，已通过网站设计者复核
- `DES-002`：设定库与关系编辑设计，`APPROVED`，依赖 `DES-001`
- `DEV-003A`：新增模型、只读迁移、校验与兼容投影，`APPROVED`；本地 505 项与 GitHub 后端、前端、PostgreSQL、Docker 全部门禁通过
- `DEV-003B`：设定安全写入、版本、来源和关系，`BACKLOG`，依赖 `DEV-003A`；写入前必须增加类型、来源和旧 ID 映射的项目级复合引用约束及错误引用测试
- `DEV-003C`：合并、项目切换和回滚演练，`BACKLOG`，依赖 `DEV-003B`
- `BUG-001`：移动端导航与工作区响应式修复，`BACKLOG`，依赖 `DES-001`
- `BUG-002`：修复历史 Alembic `Text` 与 ORM `JSON` 物理类型不一致，设计 `REVIEW`；已拆分为只读预检 `BUG-002A`、维护冻结 `BUG-002B`、迁移/恢复演练 `BUG-002C` 和真实执行 `BUG-002D`，每阶段独立批准与验收

### 开发验收重点

- 要素支持稳定 ID、类别、名称、结构化数据、来源、创建和更新时间；
- 支持任意两个要素之间的有向关系和关系说明；
- 支持自定义类别与字段定义；
- 并发更新有冲突保护，不允许静默覆盖；
- 迁移前后数据量和关键字段一致。

## M2：章节计划、首次出现与伏笔生命周期

- 建议周期：第 4–5 周
- 里程碑目标：用户能精确控制要素如何进入章节，并管理伏笔全生命周期。
- 出口标准：
  - 可将设定绑定到指定章节并选择“首次出现、引用、揭示”；
  - 可设置伏笔埋入、强化、计划回收和实际回收章节；
  - 修改章节计划时显示受影响章节和冲突；
  - 时间线可按故事时间和章节顺序查看；
  - AI 大纲只能生成建议，用户确认后才成为计划。

- `DEV-004`：章节计划与要素绑定 API，`BACKLOG`
- `DEV-005`：伏笔生命周期与时间线 API，`BACKLOG`
- `DEV-006`：章节计划工作台实现，`BACKLOG`

## M3：可追踪生成与一致性闭环

- 建议周期：第 6–7 周
- 里程碑目标：每次生成都有依据、有版本、有检查结果，用户能够理解并处理冲突。
- 出口标准：
  - 记录生成运行、模型配置、使用的设定版本、章节计划和上下文快照；
  - 重新生成产生新版本，不覆盖用户已确认内容；
  - 章节生成前执行硬约束检查，生成后执行一致性检查；
  - 冲突报告能定位角色、规则、时间线、关系和伏笔问题；
  - 用户可以忽略、修复或接受检查结果，并留下记录。

### 任务

- `DEV-007`：生成运行和内容版本模型，`BACKLOG`
- `DEV-008`：一致性检查服务接入生成与编辑流程，`BACKLOG`
- `DES-004`：版本对比与冲突处理界面，`BACKLOG`
- `DEV-009`：版本对比、恢复和检查报告界面，`BACKLOG`

## M4：长篇创作 Beta

- 建议周期：第 8–9 周
- 里程碑目标：验证至少 200 章项目的编辑、生成和一致性性能。
- 出口标准：
  - 项目不再受 50 章硬限制；
  - 200 章、核心要素 1,000 条条件下，常规列表与编辑操作可用；
  - 上下文采用分层摘要、活跃状态和相关要素检索，不只依赖最近 5 章；
  - 章节编辑会重新提取事实并提示对后续计划的影响；
  - 核心工作流完成端到端测试和一次真实小说样本试写。

### 任务

- `DEV-010`：长篇上下文与记忆压缩方案，`BACKLOG`
- `DEV-011`：性能优化和 200 章负载验证，`BACKLOG`
- `DES-005`：长列表、搜索、筛选和批量操作设计，`BACKLOG`
- `PM-003`：Beta 样本验收，`BACKLOG`

## M5：发布门禁

- 建议周期：第 10 周
- 里程碑目标：形成可上线、可监控、可恢复的 Beta。
- 出口标准：
  - 全量自动化测试、迁移演练、备份恢复和回滚演练通过；
  - 数据删除、隐私说明、日志脱敏和权限矩阵通过审查；
  - 桌面与移动端核心流程通过设计验收；
  - 键盘操作、焦点、对比度和减少动画达到项目可访问性标准；
  - 生产配置单一事实来源明确；
  - 最高管理者给出 `APPROVED` 后才允许上线。

### 任务

## 明确不在当前里程碑中的内容

- 社区推荐、排行、关注、评论等扩张；
- 模仿具体作者或作品的风格复刻；
- 新增付费模型、向量数据库或其他付费服务；
- DOCX、EPUB 等更多导出格式；
- 多人实时协作；
- 移动原生 App。

这些事项保持 `BACKLOG`，只有最高管理者确认不影响核心里程碑后才能进入 `READY`。
